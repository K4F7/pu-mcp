# 按 PU 签到计有效分，用选活动 / 待办完成自动报名和参加提醒

## Problem Statement

我要用本人 PU 账号补二课学分，但现在只能手翻活动、手填学分进度。教务学分预警是规则来源，真正能抢的活动只在 PU 上。我想一眼看到学分缺口，从列表里挑该抢的活动加入待抢，到点自动报名，然后在活动开始前被提醒去签到——因为只有签到才计有效分。学工上的志愿、创新创业、获奖和蛟湖阅读不在 PU 上，不要混进这个工具。

## Solution

本地工具只连 PU。选活动页顶上展示学分缺口，默认列出全部活动，用当前列表里实际出现的活动类型做筛选按钮。我自己把活动加入待抢。待办页分两层：待抢层到可报名时间自动报名（提前 2 小时提醒准备）；报名成功后进入已报层，展示活动时间，提前 2 小时提醒去签到。有效分认 PU 已有的已签到记录：每次 0.1，再套普通签到上限和模块上限。学时只作参考。前端用 NiceGUI 换成这两个页面。

## User Stories

1. As a 本人用户, I want 用本人 PU 账号登录本地工具, so that 只有我的会话能拉活动和报名
2. As a 本人用户, I want 登录失败或碰到验证码/风控时立即停止自动操作, so that 不会绕过学校风控
3. As a 本人用户, I want 未登录时先看到登录门而不是两个主页面, so that 不会对着空数据操作
4. As a 本人用户, I want 退出登录并清掉本地会话, so that 别人用这台电脑时拿不到我的 token
5. As a 本人用户, I want 打开选活动页就看到学分缺口, so that 我知道还差什么
6. As a 本人用户, I want 缺口里看到学术讲座有效学分对照认定标准 0.5, so that 我知道必须补还差几次签到
7. As a 本人用户, I want 缺口里看到思想引领是否已达标, so that 我不会把它当成必须补
8. As a 本人用户, I want 缺口里看到总有效分以及阶段线表（大一下 1 到大四上 6）, so that 我知道总量离哪条线还有多远
9. As a 本人用户, I want 已获每次都按 PU 已签到记录重算, so that 不用手填起点、也不会和 PU 脱节
10. As a 本人用户, I want 选活动默认列出 PU 返回的全部活动, so that 我能看到当前能抢的所有场次
11. As a 本人用户, I want 筛选按钮按当前列表里实际出现的活动类型动态生成并带「全部」, so that 没有空类型按钮
12. As a 本人用户, I want 点某个活动类型按钮只看该类型, so that 我能专注讲座或体育健身
13. As a 本人用户, I want 点「全部」恢复默认列表, so that 我能退回总览
14. As a 本人用户, I want 自己把活动加入待抢, so that 程序不会按缺口把活动自动塞进来
15. As a 本人用户, I want 待抢到可报名时间由程序自动报名, so that 我不用卡点手点
16. As a 本人用户, I want 待抢在报名开始前 2 小时出现开抢提醒, so that 我能保证账号在线、程序能抢上
17. As a 本人用户, I want 自动报名成功后自动出现在待办已报层, so that 我不用再手加参加待办
18. As a 本人用户, I want 自动报名失败时待抢标失败且不生成已报项, so that 我可以换一场再加入待抢
19. As a 本人用户, I want 已报层展示已报名活动的活动时间, so that 我知道什么时候要去现场
20. As a 本人用户, I want 活动开始前 2 小时收到参加提醒, so that 我能赶到现场签到
21. As a 本人用户, I want 只有 PU 状态变为已签到才计 0.1 有效学分, so that 报了没去不会假达标
22. As a 本人用户, I want 待办上手勾不算签到, so that 有效分只认 PU 状态
23. As a 本人用户, I want PU 变为已签到后已报项被勾掉, so that 待办里只剩还没去的
24. As a 本人用户, I want 学时只显示作参考、不代入有效分公式, so that 一场 3 学时和一场 1 学时都只按一次 0.1 计
25. As a 本人用户, I want 学术讲座没有普通签到 1 分子上限、模块上限 2, so that 我可以靠讲座把总有效分一直刷到 2
26. As a 本人用户, I want 思想引领、校园文化、社会实践、学科竞赛、体育健身普通签到最多 1 有效学分, so that 封顶后我不会以为再刷还能加总有效分
27. As a 本人用户, I want 这五类模块上限 2 但多出的 1 靠拿奖, so that 工具不会假装 PU 普通签到能把它们做到 2
28. As a 本人用户, I want 讲座签到未到 0.5 时把它当作必须补, so that 筛选和缺口优先补达标
29. As a 本人用户, I want 思想引领已达标后只跟踪不当必须补, so that 推荐不会逼我再刷思想引领
30. As a 本人用户, I want 校园文化普通签到到 1 后不再增加总有效分, so that 我不会靠刷校园文化过阶段线
31. As a 本人用户, I want 社会实践、学科竞赛、体育健身按 0.1/次计入总有效分直到普通签到上限 1, so that 讲座之外还能用这些类型凑总量
32. As a 本人用户, I want 工具不接入学工、不登录教务, so that 我只维护一套 PU 登录
33. As a 本人用户, I want 志愿服务和创新创业不作为 PU 可抢活动来处理, so that 不会出现「有活动但不计有效分」这种误导卡片——PU 上没有这类活动
34. As a 本人用户, I want 蛟湖阅读和获奖认定项目不出现在缺口和待办里, so that 我不会用这个工具去完成学工或独立任务
35. As a 本人用户, I want 待办页分成待抢和已报两层, so that 该抢的和该去的不会混成一张日历
36. As a 本人用户, I want 选活动和待办就是全部主界面（NiceGUI）, so that 不再在学分进度、计划、提醒、记录之间跳
37. As a 本人用户, I want 从待抢里取消还没开抢的活动, so that 我改主意时不会被自动报上
38. As a 本人用户, I want 已经报名成功的活动不再重复自动报名, so that 不会对同一场刷报名
39. As a 本人用户, I want 刷新后缺口跟着 PU 已签到记录变, so that 现场签到后数字马上对
40. As a 本人用户, I want 列表为空时仍能看到缺口和筛选「全部」, so that 空状态不会把页面拆掉
41. As a 本人用户, I want 活动卡片上看见报名时间和活动时间, so that 我加入待抢前知道何时开抢、何时要去
42. As a 本人用户, I want 待抢层按可报名时间排序, so that 最近要抢的排在前面
43. As a 本人用户, I want 已报层按活动开始时间排序, so that 最近要去的排在前面
44. As a 本人用户, I want 未到提前 2 小时的项目仍留在对应层但未到提醒点, so that 待办是完整安排而不是只在最后两小时才出现
45. As a 本人用户, I want 阶段线和最终 6 分只跟总有效分, so that 我不会用封顶后多出来的学时去凑线
46. As a 本人用户, I want 即使总有效分已经过阶段线，讲座未到 0.5 仍显示必须补, so that 板块达标和总量是两条约束
47. As a 本人用户, I want 同一类型第 11 次普通签到（讲座除外）不再增加有效学分, so that 上限是 1 不是无限刷
48. As a 本人用户, I want 讲座第 20 次签到后有效学分停在 2, so that 模块上限生效
49. As a 本人用户, I want 仅报名未签到的讲座不计入 0.3 那种已获, so that 必须补次数不会少算
50. As a 本人用户, I want 本地低频请求和有限重试保持现有报名计划行为, so that 自动报名仍受风控和重试上限约束
51. As a 本人用户, I want CLI 登录和报名计划仍然可用, so that 没有打开网页时也能跑自动报名
52. As a 本人用户, I want 明文密码不写入磁盘, so that 凭证仍然只在会话/钥匙串里

## Implementation Decisions

- 遵守已有 ADR：不接入学工（0001）；已获来自 PU 不登录教务（0002）；阶段线和最终 6 分只跟总有效分（0003）；有效分按签到次数 0.1/次、学时只作参考（0004）；两个主页面、NiceGUI 替换现有网页（0005）。
- 领域计算和待办状态走现有应用服务，不在页面里算学分、不在浏览器里存已获。
- 可计分活动类型：学术讲座、思想引领、校园文化、社会实践、学科竞赛、体育健身。其它类型若 PU 列表出现，仍可加入待抢并自动报名，但不计入已获、不进入缺口数字。
- 已获公式：按 PU 已签到记录，分活动类型计数 × 0.1。思想引领、校园文化、社会实践、学科竞赛、体育健身再封顶到普通签到上限 1。学术讲座不套 1 分子上限，再封顶到模块上限 2。总有效分是各类型有效学分之和。必须补剩余 = max(0, 0.5 − 讲座有效学分)。
- 已获每次从 PU 已签到记录全量重算，不把本地库或手填数当权威。
- 签到只认 PU 状态。解析已报名列表（及必要时详情）里的状态字段，映射为已签到 / 未签到。真实字段名以 PU 回写为准，测试夹具给出明确已签到标记。待办手勾不得改已获。
- 待抢复用现有报名计划：加入待抢 = 创建计划，执行时间 = 该活动可报名时间；到点现有调度器自动报名。开抢提醒是待抢层在报名开始前 2 小时的展示，不改成手点报名。
- 报名成功后已报层来自 PU 已报名且尚未已签到的活动（活动时间用于参加提醒）。报名失败保持计划失败，不进入已报层。
- 参加提醒：已报层在活动开始前 2 小时强调去签到。未到 2 小时的已报活动仍展示。
- 选活动：顶上学分缺口（讲座必须补、思想引领跟踪、总有效分、阶段线表）。列表默认全部。筛选按钮 = 「全部」+ 当前列表出现过的活动类型，不预置空的志愿服务/创新创业按钮。
- 前端：NiceGUI 两个主页面替换现有多页静态网页。登录是进页前的门，不当第三主页面。本地 HTTP 服务保留。应用服务、PU 客户端、本地库、报名调度器保留。CLI 保留。
- 现有「学分进度」手填逻辑废弃，不再作为已获来源。
- 不新增教务客户端、学工客户端、成果类拉取。不绕过验证码/风控。自动报名仍低频、有限重试。
- 阶段线按已锁定表格展示，不从教务拉。工具不推断年级；把总有效分和六条阶段线一起展示。
- 依赖：增加 NiceGUI；Python 环境用 uv。

## Testing Decisions

- 只测对外行为：给定 PU 已签到/已报名/活动列表夹具和本地报名计划，应用服务算出的已获、必须补、总有效分、待抢层、已报层、报名结果是否符合规则。不测 NiceGUI 控件结构、不测 PU 真网、不测内部函数名。
- **测试缝（唯一主缝）：应用服务。** 沿用现有 FakeClient + 本地库 + 报名计划测试方式。新行为（有效分、待办两层、加入待抢、报名成功进入已报、签到后计次）全部从应用服务断言。不要为 NiceGUI 页面再开一条主缝。
- 若必须证明状态字段能被识别，用夹具喂给应用服务（底层解析是实现细节）。只有解析在服务之外就会丢数据时，才补一条现有解析夹具测试。
- 报名到点执行继续用现有调度测试：到点调用执行报名、成功/失败/已报名跳过、风控停止。
- 先验：现有应用服务测试、调度测试、解析夹具测试、网页 API 测试（若 JSON 接口仍在）。网页静态 TS 测试随 NiceGUI 替换而淘汰，不作为本功能主测试。
- 夹具覆盖至少：讲座 3 次已签到 → 有效 0.3、必须补还差 0.2；思想引领 10 次 → 有效 1；校园文化超过 10 次仍为 1；仅报名未签到不计次；讲座 20 次封顶 2；手勾不能改变已获；报名成功后出现在已报层；报名失败不出现。

## Out of Scope

- 登录教务、拉取学分预警实时数字
- 接入学工平台
- 蛟湖阅读
- 志愿服务、创新创业板块达标（PU 上没有这类活动）
- 获奖等认定项目、成果类
- 专业课学分
- 用总学分（未封顶合计）判断阶段线
- 按学时折算有效分
- 系统按缺口自动把活动塞进待抢
- 待办手勾当作签到
- 把自动报名改成只提醒手点
- 第三主页面（独立学分页、记录页等可作为实现残留，不是产品目标）
- 绕过验证码、风控、频控
- 上传账号或活动数据到第三方

## Further Notes

- 术语以仓库根目录 glossary 为准：二课学分、有效学分、总有效分、普通签到、普通签到上限、模块上限、次、签到、PU 状态、必须补、选活动、待办、待抢、自动报名、开抢提醒、参加待办。不要用「学分」单独指二课学分，不要用「待去」代替待办已报层。
- 学分预警只提供已锁定规则，不是运行时数据源。允许工具已获和教务已认定有时差。
- 现有活动列表夹具里出现过「志愿公益」类型名。产品认定 PU 上没有志愿服务/创新创业活动可抢；实现时不要为它们做「不计有效分」徽章。若列表偶尔出现同名类型，可报名但不计入已获。
- 已报名夹具目前没有明确已签到字段。实现时要对着真实 PU 回写补映射，并更新夹具；在此之前测试用夹具里的显式已签到标记。
- 开抢提醒和参加提醒的产品形态是待办列表，不是必须做操作系统推送。若后续要做系统通知，另开 spec。
