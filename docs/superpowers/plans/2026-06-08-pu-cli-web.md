# PU CLI + Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Python CLI + local Web tool that lets a user log in with their own PU account, view PU activities with activity type and score/credit details, and schedule low-frequency signup attempts.

**Architecture:** Use a single Python package with shared service logic under CLI and FastAPI Web entry points. Keep all PU HTTP access inside one `httpx` client module, all persistence in SQLite, and all scheduled signup execution behind an APScheduler-backed scheduler with conservative retry and risk-control stop behavior.

**Tech Stack:** Python 3.11+, FastAPI, Typer, httpx, Pydantic v2, APScheduler, SQLite via SQLAlchemy 2.x or SQLModel, pytest, respx, pytest-asyncio/anyio, ruff.

---

## Implementation Boundary

Do not call real PU endpoints while implementing or testing. Do not require a real account. Use fixtures and `respx`/ASGI test clients for all behavior. The tool must explicitly state that it only supports the current user's own account, uses conservative request frequency, performs only limited retries, does not bypass captcha/risk controls, and does not perform brute-force multithreaded signup.

This workspace was reported as not being a git repository during planning. If implementation starts in a non-git directory, do not force commits. If a future executor initializes or moves into a git repository, commits are optional checkpoints, not a requirement from this plan.

```text
  test_storage.py
  test_scheduler.py
  test_service.py
  test_cli.py

```

Responsibilities:

- `config.py`: settings object, defaults, env overrides, user data paths.
- `errors.py`: typed exceptions for auth, risk control, rate limit, business, network, parse errors.
- `models.py`: Pydantic and persistence-facing models for auth sessions, activities, score items, signup plans, signup attempts.
- `security.py`: token storage abstraction, keyring integration, fallback warning, masking helpers.
- `pu_client.py`: async `httpx` wrapper for PU endpoints and auth header construction.
- `activity_parser.py`: normalize activity list/detail responses into display models, especially activity type and score/credit/point fields.
- `storage.py`: SQLite schema and repository functions for plans, attempts, cached activities, auth metadata where appropriate.
- `scheduler.py`: APScheduler integration, job restore, due signup execution, mutex/duplicate prevention, limited retry.
- `service.py`: business orchestration shared by CLI and Web.
- `cli.py`: Typer commands.
- `web_app.py`: FastAPI app, JSON APIs, and local static UI routes.
- `web_static/app.css` and `web_static/app.js`: minimal browser UI for activities, details, plans, attempts.

## Global Acceptance Criteria

- CLI and Web both work from the same service layer.
- Activity list and detail views display activity type and score/credit/point content.
- Scheduled signup is supported with conservative defaults, limited retry, and persisted attempt records.
- The app supports only the user's own account and says so in README, CLI, and Web settings/status areas.
- No captcha/risk-control bypass exists.
- No brute-force multithreaded signup exists.
- No test calls real PU endpoints.
- No real account, password, token, sid, or personally identifying fixture data is committed or documented.
- If the workspace remains non-git, final implementation report should say no commit was made because the directory is not a git repository.

## Known Non-Blocking Unknowns

- Exact PU response field names may vary by school, activity type, or API version. Treat fixtures as internal contracts and expand them only with synthetic data or user-supplied redacted samples.
- Token expiration semantics may not be explicit. Implement graceful auth failure handling and ask the user to re-login when necessary.
- Some environments may not support OS keyring. The fallback must be explicit and documented.
